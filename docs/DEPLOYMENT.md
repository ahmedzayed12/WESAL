# دليل النشر والتوسع

## 1) النشر الأول على خادم واحد (حتى عشرات الآلاف من المستخدمين)

**المطلوب:** خادم Linux (مثلًا 4 أنوية / 8GB ذاكرة / 160GB SSD) عليه Docker، ونطاقان يشيران إلى عنوان IP الخادم:
`wesal.example.com` للتطبيق و`media.wesal.example.com` للوسائط.

```bash
git clone <repo> wesal && cd wesal
cp .env.example .env
nano .env          # النطاقان + كلمات مرور قوية (openssl rand -base64 32)
docker compose up -d --build
```

ما يحدث تلقائيًا:
- Caddy يصدر شهادات HTTPS ويوزع الحمل على نسخ التطبيق (`APP_REPLICAS`) ويستبعد أي نسخة غير جاهزة (`/readyz`).
- خدمة `migrate` تطبّق مخطط قاعدة البيانات قبل تشغيل التطبيق.
- `minio-init` تنشئ حاوية الوسائط (خاصة، لا وصول عام).
- `worker` ينظف القصص المنتهية والرفوعات غير المكتملة والجلسات المنتهية كل دقيقة.
- `backup` يأخذ نسخة يومية من قاعدة البيانات في `./backups` ويحتفظ بآخر 14 يومًا.

بعد التشغيل:
```bash
docker compose ps                                   # كل الخدمات healthy
curl https://wesal.example.com/readyz               # {"ok":true,...}
docker compose exec app node scripts/make-admin.js <handle>   # بعد تسجيل حسابك
```

**التحديث دون توقف:** `git pull && docker compose up -d --build` — كل نسخة تنهي طلباتها الجارية قبل الإيقاف (SIGTERM).

**الاستعادة من نسخة احتياطية:**
```bash
docker compose exec -T postgres pg_restore -U wesal -d wesal --clean < backups/wesal-YYYYMMDD-HHMM.dump
```

> انسخ مجلد `backups/` وبيانات MinIO إلى موقع خارجي (مثل حاوية S3 أخرى) — النسخ على نفس الخادم لا تحمي من فقدانه.

## 2) قياسات الأداء الفعلية

قيست على جهاز واحد بـ 4 أنوية يشغّل **كل شيء معًا** (Postgres + التطبيق + أداة القياس)، بعملية Node واحدة، مع 50 اتصالًا متزامنًا، على بيانات:
20,000 مستخدم · 3 ملايين علاقة متابعة · 400 ألف صداقة · 500 ألف منشور (كل مستخدم يتابع ~150 ويصادق ~40).

| المسار | طلب/ثانية (عملية واحدة) | زمن الاستجابة (الوسيط) |
|---|---|---|
| `/api/v1/reels` | ~4,500 | 10ms |
| `/api/v1/users/:handle/profile` | ~3,200 | 15ms |
| `/api/v1/explore` | ~1,370 | 35ms |
| `/api/v1/feed` (الصفحة الرئيسية) | ~470 | 105ms |

تقديريًا: المستخدم النشط يطلب الصفحة الرئيسية بضع مرات في الدقيقة، فعملية واحدة تخدم آلاف المستخدمين المتزامنين، وكل نواة إضافية تضيف نسخة.
لإعادة القياس على خادمك:
```bash
node scripts/seed-benchmark.js 20000 25     # على قاعدة بيانات تجريبية فقط!
npx autocannon -c 50 -d 20 -H "cookie=sid=..." https://staging.example.com/api/v1/feed
```

## 3) التوسع لأعداد ضخمة (مئات الآلاف إلى ملايين)

التطبيق مصمم لهذا الانتقال **دون تغيير في الشيفرة** — فقط متغيرات البيئة:

| المرحلة | الإجراء |
|---|---|
| **التطبيق** | انقل حاويات `app` إلى منصة توسع تلقائي (Kubernetes / AWS ECS / Fly.io / Cloud Run). الخوادم عديمة الحالة؛ وسّع حسب استهلاك المعالج. |
| **قاعدة البيانات** | Postgres مُدار (AWS RDS / Aurora، Google Cloud SQL، Azure، DigitalOcean) مع نسخ احتياطي تلقائي ونسخة متماثلة للتعافي. ضع **PgBouncer** (وضع transaction) أمامها عندما يتجاوز (عدد النسخ × `DATABASE_POOL_MAX`) حد الاتصالات. |
| **Redis** | Redis مُدار (ElastiCache / Memorystore / Upstash). |
| **الوسائط** | `STORAGE_DRIVER=s3` مع AWS S3 أو **Cloudflare R2** (بلا رسوم نقل بيانات) أو DigitalOcean Spaces. اضبط CORS على الحاوية للسماح بـ `PUT` و`GET` من نطاق التطبيق. |
| **CDN** | ضع Cloudflare أمام التطبيق للملفات الثابتة وحماية DDoS. |

### الخطوات التالية في الشيفرة عند الوصول لهذه الأحجام
1. **نسخ قراءة (read replicas)** لمسارات القراءة الثقيلة (feed/explore/profile).
2. **خلاصة مسبقة الحساب (fan-out on write)** للحسابات العادية مع الإبقاء على السحب عند القراءة للمشاهير — حين تتجاوز شبكة المستخدم آلاف الحسابات.
3. **معالجة الفيديو**: تحويل إلى HLS بجودات متعددة وصور مصغّرة (طابور مهام + FFmpeg أو خدمة مُدارة مثل Cloudflare Stream / AWS MediaConvert)، وفحص الملفات من البرمجيات الخبيثة.
4. **بحث نصي كامل** بالعربية (pg_trgm أو OpenSearch/Meilisearch).
5. **إشعارات فورية** عبر WebSocket/SSE (Redis pub/sub موجود أصلًا)، وإشعارات الجوال.
6. **تأكيد البريد واستعادة كلمة المرور** (يتطلب مزود بريد مثل SES / Postmark)، والمصادقة الثنائية.
7. **المراقبة**: السجلات بصيغة JSON جاهزة لـ Loki/Datadog؛ أضف مقاييس Prometheus وتنبيهات وتتبع الأخطاء (Sentry).

## 4) قائمة تحقق قبل الإطلاق العام

- [ ] كلمات مرور قوية وفريدة في `.env`، والملف غير مرفوع إلى Git.
- [ ] جدار ناري يسمح فقط بالمنافذ 22 و80 و443.
- [ ] نسخ احتياطية خارج الخادم + تجربة استعادة فعلية.
- [ ] حساب مشرف واحد على الأقل، ومراجعة دورية للبلاغات.
- [ ] صفحتا **سياسة الخصوصية وشروط الاستخدام** (متطلب قانوني، ومتطلب متاجر التطبيقات) — المنصة توفر حذف الحساب وبياناته فعليًا.
- [ ] مراجعة متطلبات حماية البيانات في بلدك (مثل نظام حماية البيانات الشخصية السعودي PDPL أو GDPR للمستخدمين الأوروبيين).
- [ ] اختبار حمل على بيئة مطابقة للإنتاج.
